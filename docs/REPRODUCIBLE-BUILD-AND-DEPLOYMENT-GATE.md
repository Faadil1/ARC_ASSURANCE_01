# Reproducible Build + Deployment Manifest Gate

**Status:** ACTIVE / NOT PROVEN  
**Branch:** `chore/reproducible-build-manifest`

This gate binds reviewed source to the exact deployment transaction without pretending the runtime hash is knowable before deployment.

## Canonical provenance chain

```text
exact Git SHA
→ pinned toolchain inputs
→ clean dependency install
→ Solidity compilation
→ AssuranceVault creation bytecode
→ creation bytecode keccak256
→ exact constructor args
→ init-code keccak256
→ Arc deployment transaction input
→ successful deployment receipt
→ deployed contract address
→ observed runtime bytecode hash
```

## Why runtime hash is post-deployment evidence

`AssuranceVault` inherits EIP-712 and contains constructor immutables.

The final runtime can therefore contain constructor/address-dependent immutable values.

Accordingly:

```text
precomputed generic runtime template hash
!= guaranteed deployed runtime hash
```

The predeployment binding target is the **init-code hash**.

After deployment, the verifier must fetch:

- deployment transaction input;
- deployment receipt;
- contract address;
- deployed runtime bytecode.

The deployment transaction input must hash to the exact expected init-code hash.

## Build manifest

Generated by:

```bash
npm run build:manifest
```

Output:

`build/reproducible-build-manifest.json`

It records:

- exact Git SHA;
- Node/Forge/solc versions;
- dependency pins;
- package-lock hash when present;
- source/config SHA-256 fingerprints;
- creation bytecode keccak256;
- runtime-template hash as informational only.

## Deployment manifest

Generated by:

```bash
npm run deploy:manifest
```

It requires explicit environment values for:

- authority;
- deployment spend cap;
- policy ID;
- funder;
- provider;
- payout recipient;
- scorer hash;
- failure threshold;
- policy cap;
- unit payout;
- expiry.

The output remains:

`PREDEPLOY_NOT_LIVE`

until real Arc receipts are filled.

## Dependency lock boundary

Direct Node dependency is pinned:

`viem = 2.56.9`

But reproducibility requires the **transitive npm graph** to be locked by a committed `package-lock.json`.

Current status:

`BLOCKED_UNTIL_PACKAGE_LOCK_COMMITTED`

The CI workflow generates a candidate lock as an artifact. That artifact must be reviewed and committed before this gate can become PROVEN.

## Deterministic golden vector

The public vector no longer uses randomness.

Its test-only private key is deterministically derived in memory from:

```text
keccak256("ARC_ASSURANCE_GOLDEN_VECTOR_V1_TEST_KEY_ONLY")
```

The private key itself is never emitted.

The same vector is generated twice in clean-room CI and compared byte-for-byte.

Foundry independently recomputes:

- EIP-712 domain separator;
- provider struct hash;
- final digest;
- signer recovery;
- hidden-canary commitment;
- canary reuse key.

## Clean-room workflow

`.github/workflows/reproducible-build.yml`

It performs:

1. exact checkout;
2. Node 22.16.0;
3. candidate npm lock generation;
4. npm clean install;
5. pinned Solidity libraries;
6. deterministic golden vector twice;
7. all JS tests;
8. Solidity build;
9. build manifest;
10. deterministic CI deployment manifest;
11. Solidity tests / cross-language checks;
12. evidence artifact upload.

The CI artifact is evidence, not an automatic promotion.

## Local strict gate

```bash

```

Unlike provisional CI bootstrap, the local strict gate **requires a committed package-lock.json**.

## Promotion rule

This gate becomes PROVEN only after all of the following:

- package-lock committed and reviewed;
- clean-room workflow green on exact commit;
- JS tests green;
- Solidity tests green;
- cross-language golden vector green;
- creation/init-code hashes recorded;
- Opeyemi technical review of deployment path;
- final deployment manifest approved;
- deployment tx input matches expected init-code hash;
- deployment receipt address matches expected contract;
- observed runtime code hash captured;
- source commit/build artifact provenance retained.

No mainnet funding is authorized merely by producing these files.
